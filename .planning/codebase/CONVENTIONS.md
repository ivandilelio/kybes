# Coding Conventions

**Analysis Date:** 2026-10-17

## Languages

Kybes is a **code generator** (the kit itself is Python) that emits model/repository/test code in four target languages: Python, TypeScript, C#, Java. Conventions differ per layer.

### Kit Code (Generator)

All generator and hook scripts are pure Python 3.8+, standard library only (no PyYAML at runtime -- a custom `miniyaml.py` reader is used instead).

**Files:**
- `marketplace/plugins/kybes/scripts/gen/*.py` -- generators and emitters
- `marketplace/plugins/kybes/scripts/*.py` -- hooks and architectural rules

### Generated Code (Target Projects)

Code is emitted into target projects under `libs/db-models/{lang}/src/model/generated/`. Custom (user-editable) files sit one level up in `model/`.

## Naming Patterns

**Python (kit and generated):**
- Files: `snake_case.py` -- e.g., `emit_python.py`, `test_model.py`
- Functions: `snake_case` -- e.g., `find_by_partita_iva()`, `list_page()`
- Classes: `PascalCase` -- e.g., `ClientiRepository`, `ModelValidationError`
- Members/columns: `snake_case` -- mapped from schema PascalCase via `snake()` in `marketplace/plugins/kybes/scripts/gen/schema.py`

**TypeScript (generated):**
- Files: `PascalCase.ts` for entities, `_paging.ts` for internal modules
- Functions/methods: `camelCase` -- e.g., `findByPartitaIva()`, `listPage()`
- Classes: `PascalCase` -- e.g., `ClientiRepository`
- Members: `camelCase` -- mapped via `camel()` in `schema.py`

**C# (generated):**
- Files: `PascalCase.cs`
- Methods: `PascalCaseAsync` -- e.g., `FindByPartitaIvaAsync()`, `ListPageAsync()`
- Members: `PascalCase` (same as schema column names)
- Pattern: `partial class` for generated + custom code in same class

**Java (generated):**
- Files: `PascalCase.java`, repositories as `{Table}Repository.java`
- Methods: `camelCase` -- e.g., `findByPartitaIva()`, `listPage()`
- Members: `camelCase`

**Naming dispatch:** All naming logic is centralized in `marketplace/plugins/kybes/scripts/gen/naming.py` -- use `method_name(lang, key)`, `member(lang, name)`, `custom_file(lang, table)`.

## Code Style

**Formatting (kit Python):**
- No formal formatter configured (no `.prettierrc`, no `ruff.toml` in repo root)
- Implicit style: 4-space indent, `from __future__ import annotations` at top of every file
- Imports: stdlib first, then sibling modules (no absolute package imports -- scripts run with `sys.path` manipulation)

**Formatting (generated TypeScript):**
- No prettier/eslint in the kit itself; generated projects get their own config via scaffold

**Linting:**
- Generated Python files include `# ruff: noqa` header (suppresses linting on auto-generated code)
- Kit code follows ruff-compatible style but has no enforced config

## Import Organization

**Kit Python (`scripts/gen/`):**
1. `from __future__ import annotations`
2. Standard library (`json`, `os`, `re`, `sys`, `pathlib`)
3. Sibling modules (`from schema import ...`, `from naming import ...`, `import emit_python`)
- Path setup: `sys.path.insert(0, ...)` used to make sibling imports work without packages

**Generated Python:**
1. `from __future__ import annotations`
2. Standard library
3. SQLAlchemy / pymongo imports
4. Relative imports from `model.generated`

**Generated TypeScript:**
1. `reflect-metadata` (if TypeORM)
2. Node builtins (`node:assert/strict`)
3. Third-party (`typeorm`)
4. Relative model imports

## Error Handling

**Validation pattern (all languages):**
- `ModelValidationError` with a `fields` dict mapping field name to error message
- Raised/thrown before database operations
- Field names use the **schema name** (PascalCase), not the language-specific member name
- Example: `e.fields == {"RagioneSociale": "lunghezza massima 200"}`

**Generator errors:**
- `SchemaError` raised for invalid YAML schemas (exit code 2)
- `sys.exit(1)` for out-of-date generated files (in `--check` mode)

**Hook/rule errors:**
- Rules in `marketplace/plugins/kybes/scripts/rules.py` use severity levels: `"block"` (hard stop) or `"warn"` (advisory)
- Stop gate (`marketplace/plugins/kybes/scripts/stop_gate.py`) enforces `max_blocks: 3` before halting

## Generated File Markers

Every generated file starts with:
```
# AUTO-GENERATED by kybes. NON MODIFICARE: questo file viene rigenerato.
# Sorgente: {schema_file}. Per cambiare la tabella modifica lo schema; per i metodi custom usa il file in model/.
```
(Comment style adapts per language: `//` for TS/C#/Java, `#` for Python.)

This marker is checked by `rules.py` (`GENERATED_MARKER = "AUTO-GENERATED by kybes"`) to prevent manual edits to generated files.

## Module Design

**Generated code split:**
- `model/generated/` -- auto-generated base repositories, entities, paging, index. **Never edit.**
- `model/{Table}.py` (or `.ts`, `.cs`, `.java`) -- user-editable custom file with the repository subclass. Edit here.

**Repository pattern:**
- Base class (`{Table}RepositoryBase`) in generated code provides CRUD, relations, paging
- Custom class (`{Table}Repository`) extends base, lives in editable file
- C# uses `partial class` instead of inheritance

**Barrel/index files:**
- `model/generated/__init__.py` / `index.ts` exports all entities, `ENTITIES`, `Base`, `bindTenant`, `ModelValidationError`, `PageRequest`, `runInTransaction`, `isolationFor`

## Configuration

**Project config:** `.claude/kybes.config.json` -- defines paths, rules, dialect, model languages
- Default config defined in `marketplace/plugins/kybes/scripts/rules.py` (`DEFAULT_CONFIG`)
- Generator config defaults in `marketplace/plugins/kybes/scripts/gen/gen.py` (`DEFAULT_MODEL`, `DEFAULT_VERIFICATION`, `DEFAULT_API`)

## Architectural Rules

Enforced by `marketplace/plugins/kybes/scripts/rules.py` and `arch_check.py`:
- `orm_outside_db_models`: block -- ORM imports only allowed in `libs/db-models/**`
- `hardcoded_secrets`: block
- `protected_paths`: block -- `.claude/kybes.config.json` and `tools/kybes/**` are protected
- `generated_files`: block -- cannot manually edit files with the generated marker
- `model_layout`: block -- enforces correct file placement
- `custom_method_collision`: block -- custom methods must not collide with generated ones
- `duplicate_code`: block -- min 8 lines

## Documentation Language

All comments, docstrings, error messages, and documentation are in **Italian**. Schema field names use Italian (e.g., `RagioneSociale`, `PartitaIva`, `CreatoIl`).
