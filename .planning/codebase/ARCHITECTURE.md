# Architecture

**Analysis Date:** 2026-10-17

## System Overview

kybes is a Claude Code plugin (toolkit) that enforces consistent backend architecture through three mechanisms: deterministic code generation from YAML schemas, contextual rules for AI agents, and automated verification hooks.

```text
┌─────────────────────────────────────────────────────────────┐
│                    Claude Code Agents                        │
│  `marketplace/plugins/kybes/agents/`                        │
│   architect → implementer → reviewer                        │
├──────────────────┬──────────────────┬───────────────────────┤
│   Skills/Rules   │     Hooks        │    Generator          │
│  `skills/`       │  `hooks/`        │   `scripts/gen/`      │
│  `templates/     │  `scripts/`      │   `scripts/gen/       │
│   rules/`        │                  │    engine/`            │
└────────┬─────────┴────────┬─────────┴──────────┬────────────┘
         │                  │                     │
         ▼                  ▼                     ▼
┌─────────────────────────────────────────────────────────────┐
│              Target Project (installed by kybes-init)        │
│  schemas/db/*.yaml → libs/db-models/ → db/generated/        │
│                    → schemas/generated/ → jobs/generated/    │
└─────────────────────────────────────────────────────────────┘
```

## Component Responsibilities

| Component | Responsibility | File |
|-----------|----------------|------|
| Schema loader | Parse and validate YAML table definitions | `marketplace/plugins/kybes/scripts/gen/schema.py` |
| Generator (gen.py) | Produce model code in 4 languages from schemas | `marketplace/plugins/kybes/scripts/gen/` |
| MiniYAML | Custom YAML parser (no PyYAML dependency) | `marketplace/plugins/kybes/scripts/gen/miniyaml.py` |
| Engine | Job execution: archive, retention per table/tenant | `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/engine.py` |
| Storage | S3/Blob archive storage abstraction | `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/storage.py` |
| Codec | Serialization for archive files | `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/codec.py` |
| Config | Job configuration and partition logic | `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/config.py` |
| Rules checker | Validates architectural rules (imports, placement) | `marketplace/plugins/kybes/scripts/rules.py` |
| Model guard | Blocks ORM/driver imports outside model layer | `marketplace/plugins/kybes/scripts/model_guard.py` |
| Architecture check | Structural verification for CI | `marketplace/plugins/kybes/scripts/arch_check.py` |
| Pre-write hook | Rejects file writes that violate rules | `marketplace/plugins/kybes/scripts/pre_write.py` |
| Post-edit hook | Re-runs generator when schema changes, lints | `marketplace/plugins/kybes/scripts/post_edit.py` |
| Stop gate | Blocks task completion until all checks pass | `marketplace/plugins/kybes/scripts/stop_gate.py` |
| Hook common | Shared utilities for hook scripts | `marketplace/plugins/kybes/scripts/hook_common.py` |
| Verify | Verification script | `marketplace/plugins/kybes/scripts/verify.py` |
| Architect agent | Plans: runtime per endpoint, schema changes | `marketplace/plugins/kybes/agents/architect.md` |
| Implementer agent | Executes one task at a time | `marketplace/plugins/kybes/agents/implementer.md` |
| Reviewer agent | Independent review against checklist | `marketplace/plugins/kybes/agents/reviewer.md` |

## Pattern Overview

**Overall:** Schema-driven code generation with AI-agent workflow enforcement

**Key Characteristics:**
- YAML schemas (`schemas/db/<Table>.yaml`) are the single source of truth
- Deterministic generator produces identical output for identical schemas across 4 languages (Python, TypeScript, Java, C#)
- Generated files marked `AUTO-GENERATED by kybes` are never hand-edited; hooks enforce this
- Custom code goes in separate files (`model/<T>`) created once by the generator
- Multi-tenant isolation via column, schema, or database partitioning

## Layers

**Target Application Layers (what kybes generates/enforces):**

| Layer | Location in target project | Responsibility |
|-------|---------------------------|----------------|
| View | `frontend/` | SPA, CDN-served, SSO (OIDC) |
| API | API Gateway | Auth, throttling, validation via generated JSON Schema |
| Controller | `services/<context>/functions` or `ms` | Thin handler: middleware, service call, response |
| Service | `services/<context>/...` | Business rules, transactions (Unit of Work) |
| Model | `libs/db-models/<language>` | Data access: one file per table (generated + custom methods) |
| Data | SQL (PostgreSQL) or MongoDB, archive on S3/Blob | Storage |

**Strict rule:** Only the model layer accesses data. A hook blocks ORM/driver imports elsewhere.

## Data Flow

### Schema-to-Code Generation

1. Developer writes/edits `schemas/db/<Table>.yaml`
2. Post-edit hook triggers generator (`scripts/gen/`) automatically
3. Schema loader (`schema.py`) parses and validates YAML
4. Language-specific emitters produce code:
   - `emit_python.py` → Python models
   - `emit_db.py` → DDL, JSON Schema
   - `emit_api_typescript.py` → TypeScript API
   - `runtime_mongo.py` → MongoDB variants
   - `runtime_csharp.py` → C# models
   - `api_plan.py` → API endpoint planning
   - `mongo_plan.py` → MongoDB index planning
5. Output written to `libs/db-models/`, `db/generated/`, `schemas/generated/`, `jobs/generated/`

### Agent Workflow

1. Request → `kybes:architect` plans runtime, schema changes, method reuse
2. → `kybes:implementer` executes one task at a time
3. Write/Edit → `pre_write` hook rejects rule violations
4. → `post_edit` hook regenerates model on schema change, lints
5. → `kybes:reviewer` verifies against checklist
6. → `stop_gate` hook: arch_check + gen --check + tests must pass to close

### Runtime Selection (in target project)

| Case | Runtime |
|------|---------|
| Sync, stateless, under 10s | Lambda function (pay-per-use) |
| Over 10s, WebSocket, persistent connections | Microservice on Kubernetes behind API Gateway |
| Schedule, queue, event, batch | Job: CronJob, KEDA Job, or always-on engine |

## Key Abstractions

**JobConfig / Engine:**
- Purpose: Archive and retention job execution per table/tenant
- Location: `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/`
- Uses SQLAlchemy for DB access, custom Storage abstraction for S3/Blob

**Schema (dataclass):**
- Purpose: In-memory representation of a table's YAML schema
- Location: `marketplace/plugins/kybes/scripts/gen/schema.py`
- Supports: types (`uuid`, `string`, `text`, `int`, `bigint`, `decimal`, `bool`, `date`, `datetime`, `json`), relations (`many_to_one`, `one_to_many`), tenancy modes, API ops, archive/retention config

**Multi-tenancy:**
- Four isolation modes: `none`, `column` (RLS), `schema` (per-tenant schema), `database` (per-tenant DB)
- Defined per table in YAML; generator produces appropriate DDL and model code
- Relation constraints enforced: e.g., `column` table can reference `none` or `column` tables only

## Entry Points

**Generator CLI:**
- Location: `marketplace/plugins/kybes/scripts/gen/gen.py` (invoked as `python3 tools/kybes/plugins/kybes/scripts/gen/gen.py .`)
- Modes: generate (default), `--check` (verify only), `--index` (MODEL_INDEX.md only)

**Engine CLI:**
- Location: `marketplace/plugins/kybes/scripts/gen/engine/kybes_jobs/__main__.py`
- Purpose: Run archive/retention jobs

**Installer:**
- Location: `install.sh` (root shortcut) → `marketplace/plugins/kybes/install.sh`
- Purpose: Install kit into a target project (idempotent)

**Hooks entry:**
- Location: `marketplace/plugins/kybes/hooks/hooks.json`
- Defines: pre_write, post_edit, stop_gate hook bindings

## Architectural Constraints

- **Generated files are immutable:** Files with `AUTO-GENERATED by kybes` header must not be hand-edited; hooks and CI reject changes
- **Model-only data access:** ORM and database driver imports are blocked outside `libs/db-models/` by `model_guard.py`
- **One bounded context per function/microservice:** Each function or microservice exposes a single bounded context
- **Deterministic generation:** Same schema input must produce byte-identical output
- **No PyYAML dependency:** Custom `miniyaml.py` parser handles YAML loading

## Anti-Patterns

### Editing generated files

**What happens:** Developer modifies files under `generated/` directories
**Why it's wrong:** Changes are overwritten on next generation; `gen --check` fails in CI
**Do this instead:** Add custom methods in `model/<T>` files (non-generated counterparts)

### Importing ORM/driver outside model layer

**What happens:** Service or controller code imports database drivers directly
**Why it's wrong:** Violates layered architecture; `model_guard.py` hook rejects it
**Do this instead:** Access data only through model methods in `libs/db-models/<language>`

## Error Handling

**Generator:** Exit code 0 (up to date), 1 (out of date / orphan files), 2 (invalid schemas with errors on stderr)

**Schema validation:** `SchemaError` with list of error strings in `schema.py`

**Engine:** `JobError` for invalid tenant names or configuration issues in `config.py`

## Cross-Cutting Concerns

**Validation:** JSON Schema generated from YAML schemas for API Gateway middleware validation
**Multi-tenancy:** Configurable per table (column/schema/database isolation)
**Archival:** Configurable retention and archive to S3/Blob with Parquet format, queryable via Athena/Synapse
**CI:** `marketplace/plugins/kybes/templates/ci/architecture-check.yml` template; `.github/workflows/kit-tests.yml` for kit's own tests
