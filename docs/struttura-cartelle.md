# Struttura delle cartelle

Ogni progetto che usa kybes ha la stessa mappa di cartelle. Sapendo il nome di una tabella sai già dove trovare il suo schema, i metodi di accesso ai dati, i test, l'archivio e i job che la riguardano.

## La regola

> Tutto ciò che sta sotto una cartella `generated/` appartiene al generatore: non si modifica a mano e viene riscritto a ogni generazione. Tutto il resto è tuo.

L'unica eccezione è `MODEL_INDEX.md`, che sta nella radice del progetto per essere trovato subito. Anche lui è generato.

Ogni file generato inizia con l'intestazione `AUTO-GENERATED by kybes`. Gli hook rifiutano le modifiche a quei file e il controllo `gen --check` fallisce se qualcuno li ha toccati per altre vie.

## Mappa completa

Nella mappa `<T>` è il nome di una tabella in PascalCase (es. `Clienti`), `<t>` lo stesso nome in snake_case (es. `clienti`), `<pkg>` il package Java come percorso (es. `it/metainnovation/gestionale/model`). La colonna **Stato** indica se la cartella è già prodotta dal kit o arriva in una fase successiva della [roadmap](roadmap.md).

### Configurazione e istruzioni per Claude

| Percorso | Di chi | Contenuto | Stato |
|---|---|---|---|
| `.claude/kybes.config.json` | tuo | linguaggi, cartelle, livello delle regole, comandi di test | disponibile |
| `.claude/rules/kybes/*.md` | kit (copiate dall'installer) | regole caricate quando Claude tocca la cartella corrispondente | disponibile |
| `CLAUDE.md` | tuo, con un blocco del kit | principi e uso degli agenti, tra i marcatori `kybes:start` / `kybes:end` | disponibile |
| `tools/kybes/` | kit | plugin, generatore, hook e script di controllo (versionati con il progetto) | disponibile |

### Modello dati

| Percorso | Di chi | Contenuto | Stato |
|---|---|---|---|
| `schemas/db/<T>.yaml` | tuo | **sorgente di verità** della tabella ([specifica](schema-yaml.md)) | disponibile |
| `schemas/generated/json/<T>.schema.json` | generato | JSON Schema per API Gateway e middleware di validazione | disponibile |
| `schemas/generated/json/_page.schema.json` | generato | contratto della pagina (cursore, limite, ordinamento) | fase 2 |
| `schemas/openapi.yaml` | tuo | contratto delle API | disponibile |
| `MODEL_INDEX.md` | generato | indice di tabelle, file, metodi generati e custom, query e indici | disponibile |

### Librerie DB-Models, una per linguaggio

| Linguaggio | Punto d'ingresso (tuo) | Generato | Test generati | Test tuoi |
|---|---|---|---|---|
| C# | `libs/db-models/csharp/src/model/<T>.cs` | `libs/db-models/csharp/src/model/generated/<T>.cs`, `AppDbContext.cs` | `libs/db-models/csharp/tests/generated/<T>Tests.cs` | `libs/db-models/csharp/tests/custom/<T>CustomTests.cs` |
| Python | `libs/db-models/python/src/model/<T>.py` | `libs/db-models/python/src/model/generated/<T>.py` | `libs/db-models/python/tests/generated/test_<t>.py` | `libs/db-models/python/tests/custom/test_<t>_custom.py` |
| TypeScript | `libs/db-models/typescript/src/model/<T>.ts` | `libs/db-models/typescript/src/model/generated/<T>.ts`, `index.ts` | `libs/db-models/typescript/tests/generated/<T>.test.ts` | `libs/db-models/typescript/tests/custom/<T>.custom.test.ts` |
| Java | `libs/db-models/java/src/main/java/<pkg>/<T>Repository.java` | `libs/db-models/java/src/main/java/<pkg>/generated/<T>.java`, `<T>RepositoryBase.java` | `libs/db-models/java/src/test/java/<pkg>/generated/<T>Test.java` | `libs/db-models/java/src/test/java/<pkg>/<T>CustomTest.java` |

Lo stato è questo:
- **Model:** disponibile.
- **Test generati e tuoi:** fase 3.
- **Unit of Work e paginazione:** fase 2. Arrivano come file aggiuntivi nella stessa cartella `generated/` del linguaggio, ad esempio `generated/_uow.py` e `generated/UnitOfWork.cs`.
- **Accesso a MongoDB:** fase 6. Per le tabelle con `storage: mongo` i file sono negli stessi percorsi e con gli stessi nomi; cambia solo l'implementazione.

### Database, archivio e job

| Percorso | Di chi | Contenuto | Stato |
|---|---|---|---|
| `db/generated/ddl/<dialetto>/<T>.sql` | generato | DDL della tabella con indici e vincoli | fase 2 |
| `db/generated/indexes.md` | generato | analisi indici: query coperte, indici mancanti o ridondanti | fase 2 |
| `db/generated/tenancy/<T>.sql` | generato | policy di isolamento (row-level security o schema per tenant) | fase 4 |
| `db/generated/athena/<T>.sql` | generato | tabella esterna Athena sui file Parquet dell'archivio | fase 5 |
| `db/migrations/` | tuo | migrazioni applicate dalla pipeline | riservato |
| `jobs/<nome>/` | tuo | job applicativi | disponibile |
| `jobs/generated/_engine/` | generato | motore comune dei job del kit (archiviazione, TTL) | fase 5 |
| `jobs/generated/<t>-archive/` | generato | configurazione e manifest Kubernetes (CronJob, ScaledJob KEDA o Deployment) | fase 5 |

### Servizi, frontend, infrastruttura

| Percorso | Di chi | Contenuto |
|---|---|---|
| `services/<contesto>/functions/` | tuo | Lambda del bounded context |
| `services/<contesto>/ms/` | tuo | microservizio Kubernetes del bounded context |
| `libs/utils/` | tuo | funzioni pure condivise |
| `libs/errors/<linguaggio>/` | tuo (modello dallo scaffold) | modulo errori e middleware di validazione |
| `frontend/` | tuo | SPA statica servita da CDN |
| `infra/` | tuo | IaC (Terraform o CDK) |

### Evidenze di verifica (ISO 26262-6)

| Percorso | Di chi | Contenuto | Stato |
|---|---|---|---|
| `docs/generated/verification/traceability.md` | generato | matrice requisito → codice → test, con stato di copertura | fase 3 |
| `docs/generated/verification/<T>.md` | generato | specifica dei test di unità della tabella (classi di equivalenza, valori limite) | fase 3 |

## Come si ritrova una cosa

| Cerco | Dove guardo |
|---|---|
| le colonne di una tabella | `schemas/db/<T>.yaml` |
| come si chiama il metodo che legge i figli di una relazione | `MODEL_INDEX.md`, sezione della tabella |
| una query specifica di una tabella | il file custom `model/<T>` del linguaggio |
| perché un indice esiste | `db/generated/indexes.md` (fase 2) |
| quali test coprono un requisito | `docs/generated/verification/traceability.md` (fase 3) |
| quando i dati vecchi lasciano la tabella | sezione `archive` di `schemas/db/<T>.yaml` (fase 5) |
