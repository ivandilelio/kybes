# Generatore

Il generatore legge `schemas/db/*.yaml` e scrive il modello dati in tutti i linguaggi configurati, più JSON Schema e indice. È deterministico: a parità di schema produce byte per byte gli stessi file.

```bash
python3 tools/kybes/plugins/kybes/scripts/gen/gen.py .           # genera e aggiorna
python3 tools/kybes/plugins/kybes/scripts/gen/gen.py . --check   # verifica senza scrivere (CI, fine lavoro)
python3 tools/kybes/plugins/kybes/scripts/gen/gen.py . --index   # aggiorna solo MODEL_INDEX.md
```

Con Claude Code non serve lanciarlo a mano: parte da solo quando uno schema viene salvato.

| Codice di uscita | Significato |
|---|---|
| 0 | tutto aggiornato |
| 1 | file generati non aggiornati, file custom orfani o metodi custom in conflitto |
| 2 | schemi non validi (l'elenco degli errori va su stderr) |

## Cosa produce

| Prodotto | Quando |
|---|---|
| file generati di ogni tabella e linguaggio | sempre, sovrascritti |
| file custom (`model/<T>`) | solo se mancano: dopo la creazione sono tuoi e non vengono più toccati |
| `schemas/generated/json/<T>.schema.json` | sempre |
| `MODEL_INDEX.md` | sempre, compresi i metodi custom trovati nei file custom |
| rimozione dei file generati di tabelle cancellate | sempre; solo file con l'intestazione `AUTO-GENERATED by kybes` |

## Metodi generati per ogni tabella

| Metodo | C# | Python | TypeScript / Java |
|---|---|---|---|
| leggi per chiave | `GetByIdAsync` | `get_by_id` | `getById` |
| pagina ordinata | `ListAsync` | `list` | `list` |
| conteggio | `CountAsync` | `count` | `count` |
| esistenza | `ExistsAsync` | `exists` | `exists` |
| inserimento validato | `CreateAsync` | `create` | `create` |
| aggiornamento validato | `UpdateAsync` | `update` | `update` |
| cancellazione | `DeleteAsync` | `delete` | `delete` |
| per colonna univoca | `FindBy<Col>Async` | `find_by_<col>` | `findBy<Col>` |
| per chiave esterna | `ListBy<Fk>Async` | `list_by_<fk>` | `listBy<Fk>` |
| padre di una relazione | `Get<Rel>Async` | `get_<rel>` | `get<Rel>` |
| figli di una relazione | `List<Rel>Async` | `list_<rel>` | `list<Rel>` |

## ORM e comportamento per linguaggio

| | C# | Python | TypeScript | Java |
|---|---|---|---|---|
| ORM | EF Core 8 | SQLAlchemy 2 | TypeORM | JPA 3.1 / Hibernate 6.2+ |
| custom | stessa `partial class` | sottoclasse | sottoclasse | sottoclasse |
| transazione | `DbContext` del chiamante | `Session` del chiamante, commit fuori | `EntityManager` passato al costruttore | `EntityManager` del chiamante |
| date generate | `AppDbContext.SaveChanges` | default e `onupdate` | `CreateDateColumn` / `UpdateDateColumn` | `@PrePersist` / `@PreUpdate` |
| validazione | `<T>Validation.Validate` | `validate_<t>` | `validate<T>` | `entity.validate()` |
| errore | `ModelValidationException` | `ModelValidationError` | `ModelValidationError` | `ModelValidationException` |

In tutti i linguaggi l'errore di validazione riporta per ogni campo la regola violata (`obbligatorio`, `lunghezza massima 200`). Non riporta mai i valori, quindi si può restituire al client senza esporre dati.

## Nomi di vincoli e indici

I nomi sono identici in tutti i linguaggi, così il database ha lo stesso schema qualunque linguaggio lo crei:

| Nome | Origine |
|---|---|
| `ux_<tabella>_<colonne>` | colonna `unique` o indice `unique` |
| `ix_<tabella>_<colonne>` | indice dichiarato o indice automatico su chiave esterna |
| `qx_<tabella>_<query>` | indice creato per coprire una query dichiarata (fase 2) |

## Requisiti dei progetti generati

| Linguaggio | Requisiti |
|---|---|
| C# | `net8.0`, `Microsoft.EntityFrameworkCore` 8 e il provider del database (es. `Npgsql.EntityFrameworkCore.PostgreSQL`) |
| Python | Python 3.9+, SQLAlchemy 2 |
| TypeScript | `typeorm`, `reflect-metadata`, `experimentalDecorators` ed `emitDecoratorMetadata` nel `tsconfig` |
| Java | Jakarta Persistence 3.1, Hibernate 6.2+; con colonne `json` su PostgreSQL una libreria JSON (es. `jackson-databind`) |
